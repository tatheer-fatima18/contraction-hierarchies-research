# Contraction Hierarchies Research

A Python research implementation and experimental evaluation of **Contraction Hierarchies (CH)** for shortest-path queries in weighted road-network graphs.

This project is based on the foundational paper:

> Robert Geisberger, Peter Sanders, Dominik Schultes, and Daniel Delling.  
> *Contraction Hierarchies: Faster and Simpler Hierarchical Routing in Road Networks.*  
> 7th International Workshop on Experimental Algorithms (WEA 2008), LNCS 5038, pp. 319–333.  
> https://doi.org/10.1007/978-3-540-68552-4_24

**Paper:** [PDF](https://ai.dmi.unibas.ch/research/reading_group/geisberger-et-al-wea2008.pdf)  
**Publication record:** [Karlsruhe Institute of Technology](https://publikationen.bibliothek.kit.edu/en/1000015090)

> Academic note: this is a 2008 conference paper. Its suitability under the course's benchmark-paper venue/recency criteria should be confirmed with the instructor.

## Research Objective

The project will implement and evaluate Contraction Hierarchies and compare its shortest-path query performance with Dijkstra's algorithm. It will investigate how graph size and density influence preprocessing cost and query efficiency.

### Research Question

**How do road-network size and graph density affect Contraction Hierarchies preprocessing time and shortest-path query time, compared with Dijkstra's algorithm, in a reproducible Python implementation?**

## Planned Work

1. Implement Dijkstra's shortest-path algorithm as a baseline.
2. Implement Contraction Hierarchies preprocessing, including node ordering, witness searches, and shortcut creation.
3. Implement bidirectional CH queries and reconstruct the resulting shortest path.
4. Validate CH path distances against Dijkstra on test graphs.
5. Benchmark multiple graph sizes and densities.
6. Analyze preprocessing time, query time, visited nodes, and path correctness.

## Evaluation Metrics

| Metric | What it measures |
|---|---|
| Preprocessing time | Time required to build the hierarchy |
| Query time | Time required to answer a shortest-path query |
| Visited/settled nodes | Search effort during a query |
| Path distance | Whether the returned path has the correct shortest distance |
| Memory usage | Memory required by the graph and hierarchy (if practical to measure) |

The original paper's measurements will be treated as published reference results. Experiments run in this project will be reported separately because hardware, implementation language, and graph sizes may differ.

## Tools and Environment

- **Python** — implementation
- **NetworkX** — graph construction and validation
- **NumPy** — numerical and experimental utilities
- **Matplotlib** — plots and result visualization
- **Google Colab or a local Python environment** — execution

The initial experiments will use manageable synthetic weighted graphs. A small OpenStreetMap road-network extract may be added if time and compute allow.
